<Info>
Base Subscriptions enable recurring USDC payments through spend permissions. Users grant your application permission to charge their account periodically, eliminating the need for manual approvals on each payment. **No fees for merchants or users.**
</Info>

## How Subscriptions Work

Base Subscriptions use **spend permissions** - a powerful feature that allows users to grant revocable spending rights to applications. Once a user approves a subscription, your application can charge their account up to the agreed amount each period without requiring additional approvals.

<Steps>
<Step title="User Creates Subscription">
User approves a spend permission for your application to charge a specific amount periodically.
</Step>

<Step title="Application Charges Periodically">
Your backend charges the subscription when payment is due, up to the permitted amount per period.
</Step>

<Step title="Automatic Period Reset">
The spending limit resets automatically at the start of each new period.
</Step>

<Step title="User Can Cancel Anytime">
Users maintain full control and can revoke the permission at any time.
</Step>
</Steps>

## Quick Start

```typescript
import { base } from '@base-org/account';

// 1. Create a subscription
const subscription = await base.subscription.subscribe({
  recurringCharge: "9.99",
  subscriptionOwner: "0xYourAppAddress",
  periodInDays: 30
});

// 2. Check subscription status
const status = await base.subscription.getStatus({
  id: subscription.id
});

// 3. Charge the subscription (from your backend)
const chargeCalls = await base.subscription.prepareCharge({
  id: subscription.id,
  amount: "9.99"
});

// Execute charge with wallet_sendCalls
const result = await provider.request({
  method: 'wallet_sendCalls',
  params: [{
    version: '2.0.0',
    atomicRequired: true,
    from: "0xYourAppAddress",
    chainId: '8453',
    calls: chargeCalls
  }]
});
```

## Key Benefits

<AccordionGroup>
<Accordion title="No Manual Approvals">
Once users grant permission, you can charge automatically each period without requiring additional user interaction.
</Accordion>

<Accordion title="User Control">
Users maintain full control over their subscriptions and can revoke permissions at any time through their wallet.
</Accordion>

<Accordion title="Flexible Periods">
Support any billing period - weekly, monthly, annual, or custom intervals.
</Accordion>

<Accordion title="Partial Charges">
Charge any amount up to the permitted limit per period, enabling usage-based billing models.
</Accordion>

<Accordion title="No Merchant Fees">
Unlike traditional payment processors, Base Subscriptions have no merchant fees - you receive the full amount.
</Accordion>
</AccordionGroup>

## Implementation Checklist

<Steps>
<Step title="Set Up Your Application Address">
Ensure you have a wallet address that will act as the subscription owner (spender).
</Step>

<Step title="Implement Subscription Creation">
Add UI for users to create subscriptions with clear pricing and period information.
</Step>

<Step title="Store Subscription IDs">
Save subscription IDs in your database linked to user accounts.
</Step>

<Step title="Set Up Charging Backend">
Implement a backend service to charge subscriptions periodically.
</Step>

<Step title="Monitor Subscription Status">
Regularly check subscription status and handle cancellations gracefully.
</Step>

<Step title="Implement Retry Logic">
Add retry mechanisms for failed charges with appropriate backoff.
</Step>
</Steps>

## Security Considerations

<Warning>
**Important Security Notes:**
- Only the subscription owner address can execute charges
- Store subscription IDs securely in your backend
- Never expose your subscription owner private key in client code
</Warning>
