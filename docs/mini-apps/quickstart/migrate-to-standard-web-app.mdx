<Warning>
After April 9, 2026, the Base App treats all apps as standard web apps regardless of Farcaster manifests. Use the migration paths below to get your app working correctly in the Base App.
</Warning>

<Tip>
**Using an AI coding agent?** Install the [Migration Skill](https://github.com/base/skills) to let your agent handle this migration automatically. Run `npx skills add base/skills` and ask your agent to migrate your Farcaster mini app to a standard web app.
</Tip>

## Which migration path should I use?

Choose the right path based on your current app setup and goals:

| If you... | Use this path | Farcaster manifest required? |
| --- | --- | --- |
| Have an existing Farcaster mini app using the MiniApp SDK | ["I'm converting a mini app"](#choose-your-migration-path) below | No |
| Have a standard web app (not a mini app) and want to add it to Base App | [Register on Base.dev](https://www.base.dev) directly | No |
| Need Farcaster-specific features (frames, casts, etc.) | [Legacy Mini App flow](/mini-apps/quickstart/migrate-existing-apps) (deprecated) | Yes |

**Key point:** As of April 9, 2026, the Base App treats all apps as standard web apps. The Farcaster manifest and "Import Mini App" flow are only needed if you specifically require Farcaster integration (frames, cast actions, etc.). For most apps, simply registering on Base.dev is sufficient.

---

## What's changing

The Base App is moving from the Farcaster mini-app spec to a single model: **standard web app + wallet**, powered by Base.dev.

| Before | After |
| --- | --- |
| Farcaster manifest (`/.well-known/farcaster.json`) | App metadata on [Base.dev](https://www.base.dev) projects. Already registered apps do not need to update metadata. |
| Neynar webhooks for add/remove events | Base-owned backends (Base Account / address preferences) |
| FID-based notifications via Neynar | Wallet-address notifications via Base.dev notifications API *(coming soon)* |
| Farcaster SDK for auth and actions | wagmi + viem + Sign-In with Ethereum (SIWE) |
| Search and discovery via Farcaster | Base.dev app metadata + [builder codes](https://docs.base.org/base-chain/builder-codes/builder-codes) |

## Choose your migration path

<Tabs>
<Tab title="I'm converting a mini app">
<Tip>
**Let your agent handle this.** Install the [Migration Skill](https://github.com/base/skills) with `npx skills add base/skills` and ask your agent to migrate your Farcaster mini app to a standard web app. The skill maps deprecated SDK methods, replaces auth and wallet logic, and wires up the Base App path automatically.
</Tip>

Your app uses the Farcaster SDK. The migration replaces Farcaster-specific auth, identity, and actions with standard web patterns.

<Steps>
<Step title="Remove the MiniApp SDK">
Uninstall the Farcaster SDK packages:

<CodeGroup>
```bash npm
npm uninstall @farcaster/miniapp-sdk
```

```bash pnpm
pnpm remove @farcaster/miniapp-sdk
```

```bash yarn
yarn remove @farcaster/miniapp-sdk
```
</CodeGroup>
</Step>

<Step title="Add wallet connection">
Install wagmi and viem for wallet connection:

<CodeGroup>
```bash npm
npm install wagmi viem
```

```bash pnpm
pnpm add wagmi viem
```

```bash yarn
yarn add wagmi viem
```
</CodeGroup>

<Note>
If your app is already using wagmi/viem for wallet connection, you can skip this step.
</Note>
</Step>

<Step title="Replace auth with SIWE">
Replace Farcaster-specific auth with Sign-In with Ethereum (SIWE):

**Before (Farcaster SDK):**
```typescript
import { sdk } from '@farcaster/miniapp-sdk';

// Get user context from Farcaster
const context = await sdk.context;
const fid = context.user.fid;
```

**After (wagmi + SIWE):**
```typescript
import { useAccount, useSignMessage } from 'wagmi';
import { createSiweMessage } from 'viem/siwe';

function AuthComponent() {
  const { address, isConnected } = useAccount();
  const { signMessageAsync } = useSignMessage();
  
  const signIn = async () => {
    const message = createSiweMessage({
      address: address!,
      chainId: 8453, // Base mainnet
      domain: window.location.host,
      uri: window.location.origin,
      version: '1',
    });
    
    const signature = await signMessageAsync({ message });
    // Verify signature on your backend
  };
}
```
</Step>

<Step title="Replace SDK actions">
Replace Farcaster SDK actions with standard web equivalents:

| Farcaster SDK | Standard Web Equivalent |
| --- | --- |
| `sdk.actions.ready()` | Remove (not needed) |
| `sdk.actions.openUrl()` | `window.open()` |
| `sdk.actions.viewProfile()` | Link to profile page |
| `sdk.actions.close()` | `window.close()` |
</Step>

<Step title="Update your Base.dev registration">
Ensure your app is registered on [Base.dev](https://www.base.dev). Update your app metadata if needed:
- App name and description
- Icon and screenshots
- Supported chains
- Builder code (optional)
</Step>
</Steps>
</Tab>

<Tab title="I'm building a new app">
If you're building a new app for the Base App, start with standard web patterns:

<Steps>
<Step title="Set up your project">
Create a new web app using your preferred framework:

<CodeGroup>
```bash Next.js
npx create-next-app@latest my-base-app
```

```bash Vite
npm create vite@latest my-base-app -- --template react-ts
```
</CodeGroup>
</Step>

<Step title="Add wallet connection">
Install wagmi and viem:

<CodeGroup>
```bash npm
npm install wagmi viem @tanstack/react-query
```

```bash pnpm
pnpm add wagmi viem @tanstack/react-query
```
</CodeGroup>
</Step>

<Step title="Configure wagmi">
Set up wagmi with Base chain support:

```typescript config.ts
import { createConfig, http } from 'wagmi';
import { base, baseSepolia } from 'wagmi/chains';
import { injected } from 'wagmi/connectors';

export const config = createConfig({
  chains: [base, baseSepolia],
  connectors: [injected()],
  transports: {
    [base.id]: http(),
    [baseSepolia.id]: http(),
  },
});
```
</Step>

<Step title="Register on Base.dev">
Register your app on [Base.dev](https://www.base.dev) to make it discoverable in the Base App.
</Step>
</Steps>
</Tab>
</Tabs>

## Testing your migration

After migrating, test your app thoroughly:

1. **Wallet connection** - Ensure users can connect their wallets
2. **Sign-in flow** - Test SIWE authentication if implemented
3. **Base App preview** - Use [Base Build](https://build.base.dev) to preview your app
4. **Transaction flow** - Verify any on-chain interactions work correctly
