Cancel shares from a holder who is already denied by the token's transfer-sender policy. Removing the holder from an allowlist freezes outgoing transfers; `burnBlocked` then burns the specified shares and reduces total supply.

#### Demo

<AssetDemo flow="cancel" />

## Block, then cancel

```bash Terminal lines wrap
# Remove Bob from the allowlist bound to TRANSFER_SENDER_POLICY.
base-cast send $POLICY_REGISTRY "updateAllowlist(uint64,bool,address[])" \
  $POLICY_ID false "[$BOB]" \
  --rpc-url $RPC_URL --private-key $POLICY_ADMIN_KEY

# Burn 100.000000 EXM from the now-blocked account.
base-cast send $TOKEN_ADDRESS "burnBlocked(address,uint256)" \
  $BOB 100000000 \
  --rpc-url $RPC_URL --private-key $CANCELLATION_KEY
```

<Warning>
`burnBlocked` burns shares; it does not transfer them to the issuer. The caller needs `BURN_BLOCKED_ROLE`, and the holder must already be denied by `TRANSFER_SENDER_POLICY`.
</Warning>
