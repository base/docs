A payment collector translates a wallet-specific approval into the exact token transfer requested by `authorize` or `charge`. The escrow validates the collector type, calls it under a reentrancy guard, and requires the operator's token store balance to increase by exactly the requested amount.

## Compare the Deployed Collectors

| Collector | Token and wallet support | Payer interaction | `collectorData` |
|---|---|---|---|
| `ERC3009PaymentCollector` | ERC-3009 tokens such as USDC; EOAs and ERC-1271 wallets | One payment-specific signature | Signature bytes, optionally wrapped with ERC-6492 |
| `Permit2PaymentCollector` | Any ERC-20 supported by Permit2 | Initial token approval to Permit2, then one signature per payment | Permit2 signature, optionally wrapped with ERC-6492 |
| `PreApprovalPaymentCollector` | Standard ERC-20 tokens | Token approval plus an onchain payment pre-approval | Empty bytes |
| `SpendPermissionPaymentCollector` | Coinbase Smart Wallet | Spend-permission signature; optional MagicSpend withdrawal | ABI-encoded signature and withdrawal request |

Use only the collector address deployed with the same protocol version as `AuthCaptureEscrow`.

## Bind Approval to the Payment

The signature collectors derive their nonce or salt from a **payer-agnostic payment hash**. Compute it by setting `payer` to the zero address and asking the escrow to hash the otherwise complete `PaymentInfo`.

```typescript collector-nonce.ts lines wrap expandable highlight={1-8}
import { zeroAddress } from "viem";

const payerAgnosticPayment = { ...paymentInfo, payer: zeroAddress };
const collectorNonce = await publicClient.readContract({
  address: authCaptureEscrow,
  abi: authCaptureEscrowAbi,
  functionName: "getHash",
  args: [payerAgnosticPayment],
});
```

The token or wallet signature still authenticates the actual payer. The payer-agnostic hash lets an application prepare terms before it knows which wallet will sign, without allowing another payer to forge that signature.

## Use ERC-3009 for USDC

The payer signs `ReceiveWithAuthorization` with the payment collector as `to`. The collector uses `paymentInfo.maxAmount`, a `validAfter` value of zero, `preApprovalExpiry` as `validBefore`, and the payer-agnostic payment hash as the nonce.

```typescript sign-erc3009.ts lines wrap expandable highlight={10-15,23-31}
const [name, version] = await Promise.all([
  publicClient.readContract({ address: paymentInfo.token, abi: usdcAbi, functionName: "name" }),
  publicClient.readContract({ address: paymentInfo.token, abi: usdcAbi, functionName: "version" }),
]);

const collectorData = await payerWallet.signTypedData({
  account: paymentInfo.payer,
  domain: {
    name,
    version,
    chainId: base.id,
    verifyingContract: paymentInfo.token,
  },
  types: {
    ReceiveWithAuthorization: [
      { name: "from", type: "address" },
      { name: "to", type: "address" },
      { name: "value", type: "uint256" },
      { name: "validAfter", type: "uint256" },
      { name: "validBefore", type: "uint256" },
      { name: "nonce", type: "bytes32" },
    ],
  },
  primaryType: "ReceiveWithAuthorization",
  message: {
    from: paymentInfo.payer,
    to: erc3009PaymentCollector,
    value: paymentInfo.maxAmount,
    validAfter: 0n,
    validBefore: paymentInfo.preApprovalExpiry,
    nonce: collectorNonce,
  },
});
```

<Warning>
The ERC-3009 collector pulls `maxAmount`, even when the operator asks `authorize` or `charge` to collect less. It returns `maxAmount - amount` to the payer in the same transaction. The payer must have the full maximum available and token policy must permit both transfers.
</Warning>

The collector accepts ERC-6492-wrapped signatures for undeployed or counterfactual smart wallets.

## Use Permit2 for Broader ERC-20 Support

The payer first grants the canonical Permit2 contract a token allowance. Each payment then signs a `PermitTransferFrom` naming the deployed collector as `spender`.

```typescript sign-permit2.ts lines wrap expandable highlight={7-14,22-28}
const collectorData = await payerWallet.signTypedData({
  account: paymentInfo.payer,
  domain: {
    name: "Permit2",
    chainId: base.id,
    verifyingContract: permit2,
  },
  types: {
    TokenPermissions: [
      { name: "token", type: "address" },
      { name: "amount", type: "uint256" },
    ],
    PermitTransferFrom: [
      { name: "permitted", type: "TokenPermissions" },
      { name: "spender", type: "address" },
      { name: "nonce", type: "uint256" },
      { name: "deadline", type: "uint256" },
    ],
  },
  primaryType: "PermitTransferFrom",
  message: {
    permitted: { token: paymentInfo.token, amount: paymentInfo.maxAmount },
    spender: permit2PaymentCollector,
    nonce: BigInt(collectorNonce),
    deadline: paymentInfo.preApprovalExpiry,
  },
});
```

Permit2 transfers only the `amount` requested by the escrow, up to `maxAmount`. The deployed collector also accepts ERC-6492-wrapped signatures.

## Use ERC-20 Pre-Approval

This collector requires two payer transactions before the operator collects payment:

<Steps>
  <Step title="Approve the Collector">
    Approve enough token allowance for the payment amount.

    ```typescript approve-collector.ts lines wrap expandable highlight={5-6}
const approval = await payerWallet.writeContract({
  account: paymentInfo.payer,
  address: paymentInfo.token,
  abi: erc20Abi,
  functionName: "approve",
  args: [preApprovalPaymentCollector, paymentInfo.maxAmount],
});
await publicClient.waitForTransactionReceipt({ hash: approval });
    ```
  </Step>
  <Step title="Pre-Approve the Payment">
    Register approval for this exact `PaymentInfo` before `preApprovalExpiry`.

    ```typescript pre-approve-payment.ts lines wrap expandable highlight={4-6}
const preApproval = await payerWallet.writeContract({
  account: paymentInfo.payer,
  address: preApprovalPaymentCollector,
  abi: preApprovalCollectorAbi,
  functionName: "preApprove",
  args: [paymentInfo],
});
await publicClient.waitForTransactionReceipt({ hash: preApproval });
    ```
  </Step>
</Steps>

Pass `"0x"` as `collectorData` when the operator later calls `authorize` or `charge`. The escrow's one-collection rule prevents the registered pre-approval from funding another lifecycle for the same payment hash.

## Use a Spend Permission

The deployed collector reconstructs a fixed spend permission from `PaymentInfo`:

```typescript spend-permission.ts lines wrap expandable highlight={2-10}
const permission = {
  account: paymentInfo.payer,
  spender: spendPermissionPaymentCollector,
  token: paymentInfo.token,
  allowance: paymentInfo.maxAmount,
  period: 281474976710655n,
  start: 0n,
  end: paymentInfo.preApprovalExpiry,
  salt: BigInt(collectorNonce),
  extraData: "0x",
} as const;
```

After signing the permission with the smart wallet, encode the signature with an optional MagicSpend withdrawal request.

```typescript spend-collector-data.ts highlight={1-5}
const collectorData = encodeAbiParameters(
  parseAbiParameters("bytes signature, bytes withdrawRequest"),
  [permissionSignature, "0x"],
);
```

Pass an empty signature when the permission is already approved. Pass an encoded withdrawal request only when the collector must fund and spend through MagicSpend.

One spend permission can support repeated collection, but each Commerce Payments Protocol payment is still single-use. Create a fresh `PaymentInfo` and salt for every scheduled charge; the core protocol does not run a scheduler or create a recurring subscription by itself.

## Treat Custom Collectors as Security-Critical

A custom collector is not allowlisted by the escrow. The escrow only confirms that it reports the correct collector type and delivers the exact amount. The payer must separately trust that it:

- Derives a payment-specific nonce or salt from the complete terms.
- Allows only `AuthCaptureEscrow` to call its collection entry point.
- Cannot redirect funds or reuse residual approval for another purpose.
- Supports the token's transfer behavior without silently under-delivering.

Continue with [charge](/build-on-base/accept-payments/charge-a-payment) for immediate settlement or [authorize](/build-on-base/accept-payments/authorize-a-payment) for delayed capture.
