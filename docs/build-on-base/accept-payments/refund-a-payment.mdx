Call `refund` to reverse all or part of a charge or capture before `refundExpiry`. The protocol enforces the refundable limit and always sends tokens to `paymentInfo.payer`.

Captured funds are not retained by the escrow. A refund collector must source replacement liquidity from the operator, merchant, or another approved source.

## Understand Refund Accounting

Every successful `charge` or `capture` increases `refundableAmount` by its gross amount. Every refund decreases it.

```text Refund limit
available refund = total charged and captured - total refunded
```

Fees do not reduce this limit. If a 100 USDC capture sent 3 USDC to a fee receiver and 97 USDC to the merchant, the protocol permits up to 100 USDC of refunds.

## Fund the Deployed Refund Collector

The v1.1.0 `OperatorRefundCollector` pulls tokens from `paymentInfo.operator`. Approve only the amount your refund worker needs.

```typescript approve-refunds.ts lines wrap expandable highlight={4-6}
const approvalHash = await operatorWallet.writeContract({
  account: operatorAccount,
  address: paymentInfo.token,
  abi: erc20Abi,
  functionName: "approve",
  args: [operatorRefundCollector, refundAmount],
});
await publicClient.waitForTransactionReceipt({ hash: approvalHash, confirmations: 2 });
```

The approval is refund liquidity, not permission to increase the protocol's refundable accounting. `refund` still rejects any amount above the payment's balance.

## Submit the Refund

```typescript refund-payment.ts lines wrap expandable highlight={4-8}
const { request } = await publicClient.simulateContract({
  account: operatorAccount,
  address: authCaptureEscrow,
  abi: authCaptureEscrowAbi,
  functionName: "refund",
  args: [paymentInfo, refundAmount, operatorRefundCollector, "0x"],
});
const hash = await operatorWallet.writeContract(request);
const receipt = await publicClient.waitForTransactionReceipt({ hash, confirmations: 2 });
if (receipt.status !== "success") throw new Error("Payment refund reverted");
```

The transaction decreases `refundableAmount`, collects the exact replacement amount into the operator's token store, and forwards it to the payer atomically.

## Verify the Refund

```solidity PaymentRefunded.sol highlight={1-5}
event PaymentRefunded(
    bytes32 indexed paymentInfoHash,
    uint256 amount,
    address tokenCollector
);
```

Confirm the event, the token transfer to `paymentInfo.payer`, and the new state before marking the refund complete.

```text State transition
refundableAmount -= refundAmount
capturableAmount = unchanged
hasCollectedPayment = true
```

A payment can be partially captured, partially refunded, and still retain both capturable and refundable balances.

## Use a Custom Refund Collector Carefully

Custom refund collectors can source liquidity from the merchant or another party through ERC-3009, Permit2, or a purpose-built vault. The escrow accepts any collector that reports the refund type and delivers the exact amount.

<Warning>
Payment collectors and refund collectors are intentionally separate. Do not reuse residual payer approval to fund a refund. A refund collector must obtain independent authorization from the party providing refund liquidity.
</Warning>

## Handle Common Reverts

| Error | What to check |
|---|---|
| `InvalidSender` | Only `paymentInfo.operator` can refund |
| `AfterRefundExpiry` | Chain time reached or passed `refundExpiry` |
| `RefundExceedsCapture` | Amount exceeds current `refundableAmount` |
| `InvalidCollectorForOperation` | Supplied collector does not report the refund type |
| `TokenCollectionFailed` | Refund source did not deliver the exact amount |

Continue with [reconcile payments](/build-on-base/accept-payments/reconcile-payments) to join refunds to the original payment hash.
