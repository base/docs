---
title: "Capture an Authorization"
keywords: ["Commerce Payments capture", "capture escrow payment", "PaymentCaptured", "USDC capture Base"]
description: "Transfer authorized funds from escrow to the merchant and fee receiver before authorization expiry."
---

Call `capture` after fulfillment is ready. The operator chooses an amount no greater than the remaining `capturableAmount` and supplies an absolute fee within the payer-approved bounds for that capture.

Capture does not contact the payer or use the original collector again. It sends funds already held in the operator's token store.

## Check the Capturable Balance

```typescript capturable-balance.ts lines wrap expandable highlight={1-7}
const paymentInfoHash = await publicClient.readContract({
  address: authCaptureEscrow,
  abi: authCaptureEscrowAbi,
  functionName: "getHash",
  args: [paymentInfo],
});
const [, capturableAmount] = await publicClient.readContract({
  address: authCaptureEscrow,
  abi: authCaptureEscrowAbi,
  functionName: "paymentState",
  args: [paymentInfoHash],
});
```

Reject the fulfillment job if the amount exceeds the current balance or the chain timestamp has reached `authorizationExpiry`.

## Capture the Funds

```typescript capture-payment.ts lines wrap expandable highlight={5-9}
const amount = parseUnits("125.00", 6);
const feeAmount = parseUnits("2.50", 6);
const { request } = await publicClient.simulateContract({
  account: operatorAccount,
  address: authCaptureEscrow,
  abi: authCaptureEscrowAbi,
  functionName: "capture",
  args: [paymentInfo, amount, feeAmount, feeReceiver],
});
const hash = await operatorWallet.writeContract(request);
const receipt = await publicClient.waitForTransactionReceipt({ hash, confirmations: 2 });
if (receipt.status !== "success") throw new Error("Payment capture reverted");
```

The protocol first decreases `capturableAmount` and increases `refundableAmount`, then transfers the fee and merchant proceeds. A failed token transfer reverts the entire call.

## Verify Settlement

```solidity PaymentCaptured.sol highlight={1-6}
event PaymentCaptured(
    bytes32 indexed paymentInfoHash,
    uint256 amount,
    uint256 feeAmount,
    address feeReceiver
);
```

The state changes by the gross capture amount:

```text State transition
capturableAmount -= amount
refundableAmount += amount
```

The receiver receives `amount - feeAmount`, but `refundableAmount` increases by the full `amount`. A protocol refund returns gross captured value to the payer and must source that value through a refund collector.

<Warning>
Capture must execute strictly before `authorizationExpiry`. At the exact expiry timestamp, capture reverts and payer reclaim is available.
</Warning>

## Handle Common Reverts

| Error | What to check |
|---|---|
| `InvalidSender` | Only `paymentInfo.operator` can capture |
| `AfterAuthorizationExpiry` | The capture window has closed |
| `InsufficientAuthorization` | Amount exceeds the remaining capturable balance |
| `FeeAmountOutOfRange` | Absolute fee is outside the bounds for this capture amount |
| `ZeroFeeReceiver` | A nonzero fee was paired with the zero address |
| `InvalidFeeReceiver` | Dynamic call recipient conflicts with a fixed payment recipient |

For multiple shipments or a final amount below the reservation, see [capture a partial amount](/build-on-base/accept-payments/capture-a-partial-amount).
