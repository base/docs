---
title: "Void an Authorization"
keywords: ["Commerce Payments void", "cancel escrowed payment", "PaymentVoided", "return authorized funds"]
description: "Let the operator cancel an authorization and return all remaining escrowed funds to the payer."
---

Call `void` when an authorized order cannot be fulfilled. It clears the full remaining `capturableAmount` and returns those tokens from the operator's token store to the original payer.

Only the operator can void. The function has no expiry restriction, so the operator can act before or after `authorizationExpiry` as long as a capturable balance remains.

## Check the Order Decision

Before voiding:

- Stop any capture worker for the same `paymentInfoHash`.
- Confirm no additional shipment should settle.
- Load the original stored `PaymentInfo` without changing any field.
- Read the current `capturableAmount`; `void` always returns all of it.

There is no partial void function. To settle part and release the rest, capture the final amount first, then void the remainder.

## Void the Remaining Amount

```typescript void-payment.ts lines wrap expandable highlight={4-8}
const { request } = await publicClient.simulateContract({
  account: operatorAccount,
  address: authCaptureEscrow,
  abi: authCaptureEscrowAbi,
  functionName: "void",
  args: [paymentInfo],
});
const hash = await operatorWallet.writeContract(request);
const receipt = await publicClient.waitForTransactionReceipt({ hash, confirmations: 2 });
if (receipt.status !== "success") throw new Error("Payment void reverted");
```

## Verify the Return

```solidity PaymentVoided.sol highlight={1-4}
event PaymentVoided(
    bytes32 indexed paymentInfoHash,
    uint256 amount
);
```

The event amount is the entire balance that was capturable when the call executed.

```text State transition
capturableAmount = 0
refundableAmount = unchanged
hasCollectedPayment = true
```

If part of the payment was already captured, that amount remains refundable through the protocol. Void affects only funds still in escrow.

<Warning>
The operator and payer can race after `authorizationExpiry`: the operator may call `void`, while the payer may call `reclaim`. Only one transaction can return the remaining balance; the other reverts with `ZeroAuthorization`.
</Warning>

## Handle Common Reverts

| Error | What to check |
|---|---|
| `InvalidSender` | Transaction did not come from `paymentInfo.operator` |
| `ZeroAuthorization` | The payment was fully captured, previously voided, or reclaimed |
| Token transfer revert | The token blocks the payer, token store, or transfer behavior |

If the operator is unavailable, direct the payer to [reclaim the authorization](/build-on-base/accept-payments/reclaim-an-authorization).
