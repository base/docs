The Commerce Payments Protocol supports multiple captures against one authorization. Use this for split shipments, adjusted taxes, reduced fulfillment quantities, or any order whose final settled amount is lower than the reservation.

Each capture independently validates its amount, fee, receiver, caller, and deadline.

## Capture One Fulfillment Increment

```typescript capture-partial.ts lines wrap expandable highlight={2-8}
export async function capturePartial(amount: bigint, feeAmount: bigint) {
  const { request } = await publicClient.simulateContract({
    account: operatorAccount,
    address: authCaptureEscrow,
    abi: authCaptureEscrowAbi,
    functionName: "capture",
    args: [paymentInfo, amount, feeAmount, feeReceiver],
  });
  const hash = await operatorWallet.writeContract(request);
  return publicClient.waitForTransactionReceipt({ hash, confirmations: 2 });
}
```

Suppose 100 USDC is authorized:

| Operation | Capturable | Refundable |
|---|---:|---:|
| Authorization | 100 USDC | 0 USDC |
| Capture 60 USDC | 40 USDC | 60 USDC |
| Capture 25 USDC | 15 USDC | 85 USDC |
| Void remaining 15 USDC | 0 USDC | 85 USDC |

Voiding or reclaiming the remainder does not change the already captured refundable balance.

## Re-Read State Before Every Capture

Concurrent fulfillment workers can race for the same authorization. Serialize captures per `paymentInfoHash`, simulate immediately before submission, and reconcile the confirmed event before scheduling another increment.

```typescript remaining-authorization.ts lines wrap expandable highlight={1-6}
const [, capturableAmount, refundableAmount] = await publicClient.readContract({
  address: authCaptureEscrow,
```

## Calculate Fees Per Capture

Fee bounds apply to each capture, not to the authorization in aggregate.

```typescript capture-fee.ts highlight={1-5}
const minimumFee = amount * BigInt(paymentInfo.minFeeBps) / 10_000n;
const maximumFee = amount * BigInt(paymentInfo.maxFeeBps) / 10_000n;
if (feeAmount < minimumFee || feeAmount > maximumFee) {
  throw new Error("Fee is outside payer-approved bounds");
}
```

Integer division rounds both bounds down. For tokens with few decimals, many small captures can produce a lower aggregate minimum fee than one large capture. Apply a minimum capture size offchain if this matters to your fee agreement.

## Close the Remainder

After the final shipment:

- Call [void](/build-on-base/accept-payments/void-an-authorization) to return the remainder immediately.
- Let the payer [reclaim](/build-on-base/accept-payments/reclaim-an-authorization) after expiry if the operator does not act.
- Leave no capturable dust intentionally; surface it clearly to the payer if business rules require it to remain until expiry.
