description: "Let the payer recover remaining escrowed funds after a Commerce Payments Protocol authorization expires."
---

`reclaim` is the payer's liveness guarantee. If the operator does not capture or void an authorization, the payer can recover the full remaining `capturableAmount` at or after `authorizationExpiry` without operator cooperation.

## Check That Reclaim Is Available

```typescript reclaim-status.ts lines wrap expandable highlight={1-7}
const block = await publicClient.getBlock();
if (block.timestamp < paymentInfo.authorizationExpiry) {
  throw new Error("Authorization has not expired");
}
const [, capturableAmount] = await publicClient.readContract({
  address: authCaptureEscrow,
  abi: authCaptureEscrowAbi,
  functionName: "paymentState",
  args: [paymentInfoHash],
});
if (capturableAmount === 0n) throw new Error("Nothing remains to reclaim");
```

Use the chain timestamp, not the payer's device clock, to determine availability.

## Reclaim from the Payer Wallet

```typescript reclaim-payment.ts lines wrap expandable highlight={4-8}
const { request } = await publicClient.simulateContract({
  account: payerAccount,
  address: authCaptureEscrow,
  abi: authCaptureEscrowAbi,
  functionName: "reclaim",
  args: [paymentInfo],
});
const hash = await payerWallet.writeContract(request);
const receipt = await publicClient.waitForTransactionReceipt({ hash, confirmations: 2 });
if (receipt.status !== "success") throw new Error("Payment reclaim reverted");
```

The caller must equal `paymentInfo.payer`. A relayer cannot call `reclaim` from its own address unless the payer is a smart account that authorizes the call through its own execution flow.

## Verify the Recovery

```solidity PaymentReclaimed.sol highlight={1-4}
event PaymentReclaimed(
    bytes32 indexed paymentInfoHash,
    uint256 amount
);
```

```text State transition
capturableAmount = 0
refundableAmount = unchanged
hasCollectedPayment = true
```

If the operator partially captured the authorization, reclaim returns only the unconsumed remainder. The captured portion stays settled and may still be refunded before `refundExpiry`.

## Handle Common Reverts

| Error | What to check |
|---|---|
| `InvalidSender` | Connected account is not `paymentInfo.payer` |
| `BeforeAuthorizationExpiry` | Chain time is still below the configured expiry |
| `ZeroAuthorization` | No capturable amount remains after capture, void, or an earlier reclaim |

The operator can return funds earlier with [void](/build-on-base/accept-payments/void-an-authorization).
