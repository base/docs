Reconcile by `paymentInfoHash`. The initial `PaymentAuthorized` or `PaymentCharged` event establishes the immutable payment terms, and every later event changes either the capturable or refundable balance.

## Build the Payment Ledger

Store one payment record with:

| Field | Source |
|---|---|
| Chain, escrow version, and address | Integration configuration |
| `paymentInfoHash` | Indexed protocol event field |
| Full `PaymentInfo` | Initial authorization or charge event |
| Collected amount and collector | Initial authorization or charge event |
| Captures and fees | `PaymentCaptured` events, or the initial charge |
| Voided or reclaimed amount | `PaymentVoided` or `PaymentReclaimed` |
| Refunded amount and collector | `PaymentRefunded` events |
| Current balances | Event reduction cross-checked against `paymentState` |

Do not use receiver token transfers as the primary ledger. A fee creates multiple transfers, collector behavior varies, and refund liquidity can come from a party other than the original receiver.

## Reduce Events in Chain Order

```typescript reduce-payment-events.ts lines wrap expandable highlight={9-24}
type LedgerState = {
  collected: bigint;
  capturable: bigint;
  refundable: bigint;
  captured: bigint;
  returned: bigint;
  refunded: bigint;
  fees: bigint;
};

export function applyEvent(state: LedgerState, event: EscrowEvent): LedgerState {
  switch (event.eventName) {
    case "PaymentAuthorized":
      return { ...state, collected: event.args.amount, capturable: event.args.amount };
    case "PaymentCharged":
      return {
        ...state,
        collected: event.args.amount,
        captured: event.args.amount,
        refundable: event.args.amount,
        fees: event.args.feeAmount,
      };
    case "PaymentCaptured":
      return {
        ...state,
        capturable: state.capturable - event.args.amount,
        captured: state.captured + event.args.amount,
        refundable: state.refundable + event.args.amount,
        fees: state.fees + event.args.feeAmount,
      };
    case "PaymentVoided":
    case "PaymentReclaimed":
      return { ...state, capturable: 0n, returned: state.returned + event.args.amount };
    case "PaymentRefunded":
      return {
        ...state,
        refundable: state.refundable - event.args.amount,
        refunded: state.refunded + event.args.amount,
      };
  }
}
```

Apply events by block number, transaction index, and log index. Re-run affected payments when an overlap scan replaces logs after a reorg.

## Enforce Accounting Invariants

For an authorization flow:

```text Authorization conservation
PaymentAuthorized.amount
  = sum(PaymentCaptured.amount)
  + PaymentVoided.amount or PaymentReclaimed.amount
  + current capturableAmount
```

For settled value:

```text Refund conservation
PaymentCharged.amount + sum(PaymentCaptured.amount)
  = sum(PaymentRefunded.amount)
  + current refundableAmount
```

Also enforce:

- Exactly one collection event exists: `PaymentAuthorized` or `PaymentCharged`, never both.
- Every event after collection uses the same `paymentInfoHash` and escrow version.
- Every capture fee lies within the per-capture bounds in the stored `PaymentInfo`.
- Merchant proceeds plus fee equal the gross charged or captured amount.
- A void or reclaim amount equals the capturable balance immediately before that event.
- State never becomes negative in the reducer.

## Reconcile Onchain State

```typescript reconcile-state.ts lines wrap expandable highlight={1-8}
const [, onchainCapturable, onchainRefundable] =
  await publicClient.readContract({
    address: authCaptureEscrow,
    abi: authCaptureEscrowAbi,
    functionName: "paymentState",
    args: [paymentInfoHash],
  });
if (ledger.capturable !== onchainCapturable || ledger.refundable !== onchainRefundable) {
  throw new Error("Event ledger does not match escrow state");
}
```

A mismatch usually indicates a missing block range, wrong ABI version, unhandled reorg, or duplicate reduction.

## Report Gross, Fees, and Net Separately

For each charge or capture, report:

```text gross amount = event.amount
fee amount = event.feeAmount
merchant net = event.amount - event.feeAmount
```

The refund limit is based on gross amount, not merchant net. Keep fee reimbursement and commercial allocation separate from the protocol's refund accounting.

## Close Expired Windows

At `authorizationExpiry`, flag remaining capturable funds as payer-reclaimable. Do not recognize them as operator revenue.

At `refundExpiry`, the protocol can no longer process a refund for that payment. If your commercial policy permits later returns, account for them as an external transfer outside this protocol lifecycle.
