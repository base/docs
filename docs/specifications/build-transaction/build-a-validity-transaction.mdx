This guide uses Viem to construct, sign, submit, and monitor an EIP-8130 transaction that becomes eligible when its sender has a positive ETH balance.

<Warning>
Validity transactions are experimental. Use only a network and RPC endpoint that explicitly lists support for `base_sendRawTransactionValidity`.
</Warning>

## Prerequisites

Before submitting, you need:

- [Bun](https://bun.sh/) installed locally.
- An RPC endpoint that supports EIP-8130 and `base_sendRawTransactionValidity`.
- The endpoint's chain ID.
- A development private key funded with enough ETH for gas, the network tip, and the application transfer.

For EIP-8130 account and transaction concepts, see [Native Account Abstraction](/specifications/native-account-abstraction).

## 1. Create the Project

Install the EIP-8130 Viem branch and TypeScript runner:

```bash Terminal lines wrap expandable highlight={3-4}
mkdir validity-transaction-example
cd validity-transaction-example
bun init -y
bun add "viem@github:chunter-cb/viem#24aa695819c535ca4eac941c34cf8614cc331b05"
```

Set the preview endpoint, chain ID, and funded development key:

```bash .env lines wrap expandable highlight={1-3}
RPC_URL="https://your-validity-enabled-rpc.example"
CHAIN_ID="84538453"
PRIVATE_KEY="0xyour-funded-development-private-key"
```

Never use a production key in an experimental integration.

## 2. Construct and Submit the Transaction

Create `send-validity-transaction.ts`:

```typescript send-validity-transaction.ts lines wrap expandable highlight={31-38,48-56,60-70}
import {
  createPublicClient,
  defineChain,
  http,
  type Hex,
} from "viem";
import { privateKeyToAccount } from "viem/accounts";
import {
  encodeWalletCalls,
  estimateGas,
  prepareTransaction,
  toEoaAccount,
  waitForTransactionReceipt,
} from "viem/eip8130";

const rpcUrl = process.env.RPC_URL;
const chainId = Number(process.env.CHAIN_ID);
const privateKey = process.env.PRIVATE_KEY as Hex | undefined;

if (!rpcUrl || !Number.isSafeInteger(chainId) || !privateKey) {
  throw new Error("Set RPC_URL, CHAIN_ID, and PRIVATE_KEY in your environment.");
}

const chain = defineChain({
  id: chainId,
  name: "Base Validity Preview",
  nativeCurrency: { name: "Ether", symbol: "ETH", decimals: 18 },
  rpcUrls: { default: { http: [rpcUrl] } },
});

const client = createPublicClient({ chain, transport: http(rpcUrl) });
const owner = privateKeyToAccount(privateKey);
const account = toEoaAccount(owner);

const sequencerFeeVault = "0x4200000000000000000000000000000000000011";
const recipient = "0x000000000000000000000000000000000000dEaD";
const validBefore = BigInt(Date.now() + 20_000);

const calls = encodeWalletCalls({
  account: account.address,
  calls: [
    [{ to: sequencerFeeVault, value: 10_000_000_000_000n }],
    [{ to: recipient, value: 1n }],
  ],
});

const estimatedGas = await estimateGas(client, {
  sender: account.address,
  calls,
});

const transaction = await prepareTransaction(client, {
  account,
  calls,
  gas: (estimatedGas * 120n) / 100n,
  validBefore,
});

const signedTransaction = await account.signTransaction(transaction);

const hash = (await client.request({
  // @ts-expect-error Experimental Base RPC method is not in Viem's standard schema.
  method: "base_sendRawTransactionValidity",
  params: [
    signedTransaction,
    {
      validity: [
        {
          type: "balance",
          params: { address: account.address, op: ">=", value: "0x1" },
        },
      ],
    },
  ],
})) as Hex;

console.log("Submitted:", hash);

const receipt = await waitForTransactionReceipt(client, { hash, validBefore });
console.log("Included in block:", receipt.blockNumber.toString());
console.log("Phase statuses:", receipt.eip8130.phaseStatuses);
```

The transaction contains two phases:

1. The first phase transfers the network tip to the Sequencer Fee Vault.
2. The second phase transfers one wei to the burn address as the example application action.

<Warning>
Completed EIP-8130 phases persist if a later phase reverts. If the tip phase succeeds and an application phase fails, the tip can still be paid.
</Warning>

The balance predicate is true while the sender has at least one wei. Replace it with the application-specific conditions described in [Predicates and Safety](/specifications/build-transaction/predicates-and-safety).

## 3. Run the Example

Load the environment variables and run the script:

```bash Terminal highlight={1-2}
source .env
bun run send-validity-transaction.ts
```

The script prints the transaction hash after the RPC accepts it. It then waits until the transaction is included or its EIP-8130 validity window closes.

```text Expected Output
Submitted: 0x6c783c4e4f9a65d1a36ef9c8f7f30104f615a8b4cb296d3a8b4f3c972f7c13e1
Included in block: 12345678
Phase statuses: [ "0x1", "0x1" ]
```

If the script reports insufficient funds, fund the address printed by `account.address` before running it again. If it reports that the RPC method does not exist, use a validity-enabled endpoint.

## 4. Monitor the Transaction Separately

Use [`base_transactionStatus`](/base-chain/api-reference/flashblocks-api/base_transactionStatus) to check whether the transaction is known to the endpoint. A `Known` result does not mean the transaction is currently eligible.

Use [`eth_getTransactionReceipt`](/base-chain/api-reference/ethereum-json-rpc-api/eth_getTransactionReceipt) to detect inclusion. A `null` receipt means the transaction has not been included in a block visible to that endpoint.

Stop waiting when:

- A receipt is returned.
- The EIP-8130 validity window closes.
- Your application replaces or abandons the transaction.

For the complete request schema and error responses, see [`base_sendRawTransactionValidity`](/specifications/build-transaction/base_sendRawTransactionValidity).

## Use a Specific Flashblock Position

Use separate `block_number` and `flashblock_index` predicates to constrain both values:

```json Position Predicates lines wrap expandable highlight={4,11}
{
  "validity": [
    {
      "type": "block_number",
      "params": {
        "op": "=",
        "value": "0x12345"
      }
    },
    {
      "type": "flashblock_index",
      "params": {
        "op": "=",
        "value": "0x7"
      }
    }
  ]
}
```

Every predicate in the array must match at the same candidate insertion point.
