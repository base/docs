A successful submission returns a transaction hash, but it does not guarantee inclusion. Validity transactions do not expose a public pending-status, event, log, or trace API. Use [`eth_getTransactionReceipt`](/base-chain/api-reference/ethereum-json-rpc-api/eth_getTransactionReceipt) to confirm onchain inclusion.

## RPC Method Is Unavailable

**Likely cause:** The endpoint or network does not support experimental validity transactions.

**Resolution:** Use vibenet while the feature is in preview. Mainnet and Base Sepolia support is planned with the Cobalt hardfork. The method is not allowlisted, but standard transaction-submission rate limits apply.

## Submission Fails

Ensure that the transaction is a valid signed EIP-8130 transaction and that every predicate uses a supported type and operator.

- Supported predicate types are `balance`, `storage`, `block_number`, and `flashblock_index`.
- Supported operators are `<`, `<=`, `=`, `!=`, `>`, and `>=`.
- All predicates must be satisfied at the same candidate insertion point.
- The first call phase must contain a single ETH transfer to the Sequencer Fee Vault.

The published API does not yet define a stable error catalog. Record the exact JSON-RPC error returned by the endpoint when escalating an issue.

## Transaction Was Submitted but Not Included

A transaction can remain unincluded when:

- One or more predicates are false.
- Another transaction has a higher priority score.
- The builder skips validity transactions for the remainder of a Flashblock under rare conditions, such as heavy transaction load.
- The transaction is replaced by another transaction with the same nonce.
- Its EIP-8130 expiry passes before inclusion.

After each transaction, the builder evaluates predicates again. A transaction whose predicate becomes true can compete for inclusion immediately in the same Flashblock, but it is not guaranteed blockspace.

## Transaction Expired

EIP-8130 expiry is evaluated against canonical block time. There is no minimum expiry. The current target maximum and default are 60 seconds, but this can change; set an explicit expiry in every transaction.

An expired transaction cannot be refreshed. Construct, sign, and submit a replacement with a new expiry. The replacement must increase `maxFeePerGas` by at least 10%, while `priorityFeePerGas` remains `0`.

## Insufficient Funds

Confirm that the transaction can pay normal execution fees, its ETH network tip, and any ETH value sent by its application calls. A transaction that never lands onchain pays no fees.

## Get Help

When escalating an issue, include the network, RPC provider, transaction hash, predicate types, submission time, and exact JSON-RPC error. Do not share private keys, authentication data, or full signed transactions in public support channels.

For community support, use the `#developer-chat` channel in the [Base Discord](https://base.org/discord).
