## RPC Method Not Found

**Symptom:** The endpoint returns JSON-RPC error `-32601` or reports that `base_sendRawTransactionValidity` is unavailable.

**Likely cause:** The endpoint or network does not have experimental validity transactions enabled.

**Resolution:** Use only an endpoint that explicitly lists support for the method. Standard Base RPC endpoints may not expose experimental methods during a limited preview.

## Invalid Parameters

### Malformed Serialized Transaction

The first parameter must be one signed, serialized EIP-8130 transaction encoded as a `0x`-prefixed hex string. A structured transaction object is not accepted in its place.

Recreate and sign the transaction with the supported EIP-8130 client before calling the validity RPC.

### Invalid Predicate Shape

Each predicate must contain a supported `type` and a nested `params` object. Common mistakes include:

- Using `slot` as the predicate type instead of `storage`.
- Omitting `address` from a `balance` or `storage` predicate.
- Putting `block_number` and `flashblock_index` in the same predicate object.
- Encoding quantities as decimal strings instead of `0x`-prefixed quantities.
- Adding fields that are not supported by the selected predicate type.

### Storage Value Outside the Mask

For a storage predicate, every bit set in `value` must also be allowed by `mask`.

For example, `mask: "0xff"` cannot be compared with `value: "0x1ff"`. Expand the mask or correct the expected value.

### Unsatisfiable Position Predicate

A Flashblock or block-number upper bound can already be in the past when the transaction is submitted. Recompute the target position and sign a new transaction with an updated EIP-8130 validity window.

## Transaction Is Known but Not Included

A `Known` status confirms that the endpoint recognizes the hash. It does not confirm that:

- Every predicate currently matches.
- The transaction has the highest priority score.
- The transaction fits within current block limits.
- The EIP-8130 validity window remains open.

Check the observed balance, storage value, block number, and Flashblock index. Also confirm that `maxFeePerGas` can cover the current base fee and that the account can fund both gas and its network tip.

## Transaction Status Is Unknown

An `Unknown` response is not a detailed terminal status. Depending on the endpoint, it can mean that the transaction was never received, is no longer retained, expired, was replaced, or was evicted.

Confirm that the submission returned the expected hash, then query the transaction receipt and explorer before submitting a replacement.

## Predicate Matched but the Transaction Did Not Land

Predicate satisfaction makes a transaction eligible; it does not reserve blockspace. The transaction can still lose to a higher priority score, become invalid after another state change, or expire before selection.

Use a validity window that covers the expected opportunity and a network tip appropriate for the transaction's gas limit and urgency.

## Transaction Expired

An EIP-8130 transaction cannot be included after its upper validity bound. A block-number or Flashblock upper-bound predicate can also become permanently unsatisfiable.

Expired transactions cannot be refreshed because changing the validity window changes the signed transaction. Construct, sign, and submit a replacement.

## Included Transaction Reverted

Validity predicates do not guarantee successful application execution. Inspect the EIP-8130 receipt's per-phase results and trace the failing call where tracing is available.

Remember that completed earlier phases persist. A first-phase network tip can remain paid even when a later action phase reverts.

## Insufficient Funds

Confirm that the sender or payer can cover:

- The transaction's maximum execution cost.
- Any EIP-8130 account setup or authentication cost.
- The first-phase network tip.
- Any value transferred by later application phases.

If the balances change while the transaction waits, a previously affordable transaction may no longer execute successfully.

## Get Help

When escalating an issue, include the network, RPC provider, transaction hash, predicate types, submission time, and exact JSON-RPC error. Do not share private keys, authentication data, or full signed transactions in public support channels.

For community support, use the `#developer-chat` channel in the [Base Discord](https://base.org/discord).
